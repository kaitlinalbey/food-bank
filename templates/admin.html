5. Backup and recovery

Backups use SQLite's online backup API, so the copy stays consistent while the system is running. Each backup is checked (integrity, foreign keys, required tables) and recorded with a SHA-256 checksum. Backup files are kept in an admin_backups folder next to the database and are never deleted by this page.

Restoring the live database

There is deliberately no button that replaces the active database. A live restore is a planned maintenance task: stop all servers, restore the chosen backup to a new file with restore_database.py, check it, and only then switch to it. The full step-by-step procedure is in docs/DATABASE_MAINTENANCE.md.

6. Classroom demo tools

  • Distributed System Test Lab: open More tools → Test lab. Each scenario runs against its own temporary database and never touches this data.
  • System status and request traces: System status.
  • Offline sync and the outage simulation: Offline sync.
  • Fresh fictional demonstration: stop the servers, then double-click run_presentation_windows.bat (or run python start_presentation.py). Each run creates a new folder under data/presentation_sessions/; the normal data/food_bank.db is not changed.

Destructive reset tools are intentionally not on this page. The command-line reset_demo.py is for demo data only; see START_HERE.md.
